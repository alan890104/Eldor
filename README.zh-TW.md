# 艾爾多 Eldor

和精靈立約，修補碎裂的世界。收集、培養精靈，用技能與伏技展開心理戰。網頁上就能玩，3D 精靈搭配 2.5D 世界。

[開始玩](https://eldor.pages.dev)&emsp;[English](README.md)

[![艾爾多宣傳片](https://img.youtube.com/vi/nc8aHfAzebs/maxresdefault.jpg)](https://youtu.be/nc8aHfAzebs)

> 世界之心碎裂一千年後，星門重新點亮，沉睡千年的初契之龍在你面前醒來。你成為新的「締約者」，與精靈立下契約，尋回八枚源晶，阻止虛蝕吞沒世界。

目前階段：**可遊玩版本**。完整的主線（序章＋九個地區＋結局）、星門召喚、培養突破、競技場與圖鑑都能玩。

## 怎麼做出來的

艾爾多由 coding agent（Claude Code）開發：我寫設計、指揮方向；其中一晚，agent 在我睡覺時自己連續開發了六小時，就是上面那支影片。所有配樂都在瀏覽器裡即時合成，所有精靈都用程式建模。

[docs/prompts.md](docs/prompts.md) 收錄重建它的九則提示詞，照製作順序排列：遊戲概念、技術堆疊與架構、程序化角色建模、渲染管線、打擊感與絕招演出、粒子與特效、開放場景、合成樂器、配樂引擎。每則都很短，只寫技術堆疊、關鍵技術和要達成的效果，程式全部由代理自己寫。

## 怎麼玩

| 系統 | 內容 |
| --- | --- |
| **野外** | 世界地圖上九個地區，每個地區都是一片可以自由走動的 3D 野外（WASD／搖桿、奔跑、跳躍、第三人稱鏡頭）：城鎮與居民、地標、寶箱、小地圖；野生精靈在野外遊蕩（有的怕人、有的好奇、蝕化的會衝過來），碰到就開戰 |
| **伏魔塔** | 每個地區盡頭的伏魔塔就是主線關卡（6～8 層：蝕化精靈群、對戰、教團、勁敵），頂層是源晶試煉；由下往上依序突破，全部突破才能前往下一個地區。塔的封印鬆動時，虛蝕會侵蝕塔周圍的土地，每突破一層侵蝕就退一些 |
| **蝕化** | 被虛蝕侵染的精靈：紫黑身體、發光裂紋、背上長虛晶、紅眼、黑霧。戰鬥中力量／魔力 ×1.2、每回合失去 1/12 生命、怕光（×1.3），無法捕捉；擊倒即淨化，淨化後有機會願意締約，並掉落突破石 |
| **戰鬥** | 回合開始時雙方同時選技能。靈能每回合 +2，技能 0～4 費；伏技蓋在場上等對手觸發；第二次突破（Lv 40）後解鎖一場一次的奧義；每隊還有一個戰技（破陣之誓、守護之誓、疾風之誓、看破之眼、淨化之光、靈能湧泉） |
| **捕捉** | 野外碰到的野生精靈可以捕捉，對手生命越低，擲出契約石越容易成功 |
| **背包** | 「精靈」分頁分為「出戰隊伍」三格與「倉庫」（未出戰的精靈，可排序、篩選可突破），右側為能力、突破與技能；「技能配置」為獨立的全寬編輯畫面（技能欄四格＋可攜帶技能＋說明，技能欄滿時可直接替換）；「道具」分頁：所有貨幣與道具的說明、用途、取得方式，以及使用經驗藥水、兌換星塵 |
| **出戰前** | 對手資訊、出戰隊伍三格與可選精靈，標示屬性剋制對手的精靈；戰技在下方選擇 |
| **結算** | 左側展示精靈，右側大面板：經驗值（升級、習得技能、等級上限提示）、獎勵（圖示＋名稱＋數量）、戰敗時的提升建議 |
| **培養** | 戰鬥得經驗、經驗藥水直接升級；等級到上限（Lv 20／40）後需用金幣＋突破石突破才能繼續升級；技能配置 4 格，專屬技能每 5 級解鎖 |
| **星門召喚** | 契約券或 150 星輝石一抽，十連保底 SR、**50 抽必出 SSR**；重複的精靈提升共鳴 |
| **競技場** | 10 階對手，所有精靈拉平到 Lv 60、第三階段、隊伍費用上限 12，比配隊與戰術 |
| **任務** | 22 個長期目標（冒險、收集、培養、競技），達成後在主城領取獎勵 |

說明：任何畫面右上角的「?」為說明書（屬性相剋、如何變強、完整術語表）；技能與特性說明中的術語可點選查看解釋；貨幣圖示滑鼠停留或點選可查看用途；主城左上角與戰敗結算會列出提升實力的建議。

操作：滑鼠或觸控。技能卡按一下出招、停留看說明；卡片左上是種類圖示、右上是靈能費用，下緣紅條是預估傷害，出現 KO 代表能打倒對手；異常狀態以圖示顯示，點一下看說明；出戰前能看到對手陣容；3D 展示台可以拖曳旋轉；戰鬥中可切換 2 倍速與自動戰鬥。畫質預設自動（卡頓時會自動降級）。建議開聲音。

## 執行遊戲

```bash
npm install
npm run dev          # 開發伺服器 http://localhost:5173
npm run build        # 輸出到 dist/
npm run music        # 試聽配樂
```

網址參數（測試用）：`?lowfx` 低畫質、`?hq` 強制高畫質、`?nomusic` 關音樂、`?devsave` 中期測試存檔、`?devsave=late` 只差最終關的存檔、`?viewer` 精靈模型檢視器、`?arena=<地區>` 戰鬥場地檢視器（可加 `&field=<屬性>`、`&cam=showcase`、`&corrupt=1` 對手蝕化）、`?viewer&corrupt=half` 精靈與蝕化形態對照、`?fieldview=<地區>` 野外檢視器（WASD 走動；可加 `&cam=overview|tower|town`、`&at=x,z&yaw=角度`、`&done=N` 伏魔塔進度、`&check` 可達性檢查）。

## 雲端存檔（Cloudflare）

進度存在瀏覽器的 localStorage，並**自動備份到雲端，玩家不用登入**：第一次有進度要存時，瀏覽器會默默建立一個匿名帳號（一組金鑰，只存在這台裝置），之後每次存檔都自動上傳。換裝置時可在「設定 → 進階」取得轉移碼，在另一台裝置輸入即可接續；也可以在那裡關掉雲端備份。伺服器是一個 Cloudflare Worker（`worker/`），同時提供靜態網站與 `/api/*`，存檔放在 D1（SQLite）。免費方案就夠用。

| 位置 | 內容 |
| --- | --- |
| `worker/src/index.ts` | API：建立帳號、驗證金鑰、讀寫刪存檔（用 `rev` 偵測兩台裝置互相覆蓋） |
| `worker/schema.sql` | D1 資料表（`accounts`、`saves`） |
| `worker/wrangler.jsonc` | Worker 設定（靜態資源目錄 `dist/`、D1 綁定） |
| `src/game/cloud.ts` | 瀏覽器端：自動建立匿名帳號、開機同步、存檔後 4 秒自動上傳、關閉分頁時立即上傳、衝突處理 |
| `src/game/cloudSync.ts` | 純邏輯：本機與雲端哪一份該留下（有測試） |
| `src/ui/screens/Cloud.tsx` | 設定畫面的雲端備份區塊（狀態、衝突處理、進階：轉移碼） |

同步規則：開機時先下載，沒進度的那份讓給有進度的，都有進度就比存檔時間；遊玩中只上傳，若雲端被另一台裝置寫了更新的進度，會在設定畫面讓玩家選擇保留哪一份。金鑰只存 SHA-256，伺服器拿不到原文；金鑰遺失無法找回。

雲端備份預設關閉：只有建置時設 `VITE_CLOUD=1`（`npm run cloud:deploy` 會帶）才會連 `/api`，否則遊戲只用本機存檔，設定畫面也不顯示雲端區塊。

### 本機開發

```bash
npm run cloud:db:local       # 建立本機 D1 資料表（只需一次）
npm run cloud:dev            # Worker 跑在 http://localhost:8787（需要先 npm run build 產生 dist/）
VITE_CLOUD=1 npm run dev     # Vite 會把 /api 代理到 8787
```

### 部署到 Cloudflare

只部署能玩的網站（沒有雲端備份、不需要 D1）：

```bash
npx wrangler login
npm run deploy                        # 建置並上傳 dist/（worker/wrangler.static.jsonc）
```

含雲端備份（Worker 名稱相同，網址不變）：

```bash
npx wrangler login
npx wrangler d1 create eldor          # 把印出的 database_id 填進 worker/wrangler.jsonc
npm run cloud:db                      # 在正式資料庫建表
npm run cloud:deploy                  # 建置並部署（網站與 API 同一個網址）
```

建議在 Cloudflare 儀表板加一條免費的 WAF 速率限制規則（例：同一 IP 對 `/api/account` 每分鐘最多 5 次），避免有人灌帳號。

免費額度（以 Cloudflare 定價頁為準）：Workers 每天 100,000 次請求、D1 每天 100,000 列寫入與 500 萬列讀取、5 GB 儲存；一份存檔約 2～10 KB，每次存檔一次寫入。測試用的 `?devsave` 存檔不會同步到雲端。

## 開發

需要 Node.js 22.18 以上（直接執行 TypeScript）。

```bash
npm test             # 設計約束測試＋戰鬥引擎測試
npm run report       # 重新產生 docs/catalog/ 下的圖鑑、技能表、平衡報告
npm run typecheck    # TypeScript 型別檢查
```

### 程式結構

| 路徑 | 內容 |
| --- | --- |
| `data/spirits.json`、`data/skills.json` | 精靈與技能資料 |
| `sim/` | 核心公式、技能預算、抽卡機率、打擊感參數、平衡分析與報告 |
| `src/engine/` | 純 TypeScript 的戰鬥引擎（決定性、輸出事件）與 AI |
| `src/game/` | 存檔、主線關卡、養成突破、召喚、競技場 |
| `src/render/` | Three.js 渲染：卡通著色＋描邊、程序化精靈模型、九種戰鬥場景、粒子與特效、後製 |
| `src/battle/` | 戰鬥導演：把引擎事件演成動畫（頓幀、震屏、慢動作、奧義運鏡、伏技翻牌） |
| `src/audio/` | Web Audio 即時合成的音效與程序化配樂 |
| `src/ui/` | React 介面：各畫面、戰鬥 HUD、流程 |
| `tools/` | 無頭瀏覽器截圖與自動遊玩腳本（`play.mjs`）、全畫面回歸截圖（`regress.mjs`） |
| `worker/` | Cloudflare Worker：雲端存檔 API 與靜態網站（見「雲端存檔」） |

### 修改數值的流程

1. 改 `data/*.json` 或 `sim/formulas.ts`
2. `npm test`：確認沒有技能超出預算、種族值符合稀有度
3. `npm run report`：更新圖鑑與平衡報告，檢查擊倒次數與對戰矩陣
4. 如果改到文件中引用的數字（例：抽卡綜合機率），同步更新對應的文件
